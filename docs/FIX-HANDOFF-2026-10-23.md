# WordPaper 菜单栏与更新链修复交接

日期：2026-10-23。基线 `b1f5ec7`，当前为未提交的工作区改动。此前 [回测报告](RETEST-2026-10-23-menubar-updater.md) 保留修复前证据，原 handoff 的通过结论不能代替本次验证。

## 修复内容

- **菜单栏更新入口**：初始状态就有当前版本和可点击的“检查更新”；检查过后仍可再次检查。菜单每 5 秒读取主服务权威更新状态，与网页发起的安装同步；查询不到版本时不会宣称已经最新。
- **更新失败与恢复**：网页和本机菜单共用 `beginUpdate`。失败保留服务并记录错误，重试清除旧错误；只有安装成功才安排退出。网页在正常状态响应和重连响应中都会判断目标版本，修复快速重启后误报卡住。
- **原生生命周期**：JXA 同时检查实际父 PID 和有效 HTTP owner 心跳；无效/空 NSData 不再清零失联计数，退出直接调用 libc。统一停止伴侣时清理窗口、菜单和热键；菜单进程崩溃后会被重新拉起。小词灵脚本与 PNG 按 PID 分开，渲染回调加代次校验，防止隐藏后异步回调又弹出旧窗口。
- **启动器**：先验证已保存端口上的 WordPaper 再选择新端口；启动阶段加锁，重复打开复用已有服务。只清理本服务链上经工作目录确认的 bundle 进程，兼容 Slim 使用系统 Node。重复打开不会提前清掉正在等待重启的旗标。
- **完整更新与回滚**：打包加入 assets；清单记录 launcher/Info.plist 摘要；更新器同步目标清单、资源和这两个 bundle 文件。修改前备份，安装过程中抛错则恢复；启动器原子替换，保留执行权限。重启旗标写临时文件后 rename，写入失败也回滚，且不留下半个旗标。恢复本身失败时保留备份并报告路径。
- **测试可靠性**：修正 npm 用 Node 执行 Python 的错误；更新测试使用隔离数据目录，不再写真实用户重启旗标；版本查询通过显式测试 preload 固定输入。加强精确版本/清单、安装失败和末尾写旗标失败的断言。

## 交付边界和后续事项

- **已安装 App 仍为 2.4.4，仓库 VERSION 仍为 2.4.5**。本次没有提交、推送、发布或替换 `/Applications/WordPaper.app`；构建回归的临时 DMG 用完即清理。源码修复不会自动进入用户当前运行的旧 App。
- 首次交付应提升版本并完整构建、安装新 DMG。旧版 updater 不复制 launcher/Info.plist，单靠旧版“一键更新”无法一次带上全部启动器修复；新 updater 安装后，后续版本才可同步这些文件。
- 更新器能处理可捕获的安装错误；**不是断电或 SIGKILL 下的整包事务**。Node 运行时和 Mach-O stub 不在本轮热替换范围；其变更仍需完整安装。
- 临时 DMG 测试验证本地安装，不代表生产 GitHub/镜像下载、发行者身份签名、Intel 真机或 Slim 首次在线下载已通过。版本仍取 main/VERSION，发布顺序应避免先提示版本、后上传资产的空窗。
- 本轮未更改用户真实桌面壁纸，未重做 TCC 授权；原生回归检查进程和接口状态，未逐像素验收系统菜单栏。

回归脚本可直接复用，无需修复前诊断脚本的 `/tmp` 手工预载步骤。
